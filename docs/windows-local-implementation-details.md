# Windows 单机版实施细则

> 更新时间：2026-05-13  
> 目标分支：`future/windows-local`  
> 基础分支：`future/windows-base`  
> 适用范围：个人本机、离线演示、小范围本地使用。

## 1. 实施目标

Windows 单机版的目标是让普通用户安装或解压后可以直接使用在线学习平台，不需要理解数据库、命令行、MySQL、Redis 或后端启动细节。

最终用户体验应接近：

1. 双击启动程序。
2. 程序自动准备本地数据目录。
3. 程序自动初始化数据库和种子数据。
4. 程序自动启动后端与前端静态服务。
5. 程序自动打开浏览器访问本机页面。

## 2. 分支约束

单机版专属改动必须在：

```bash
git switch future/windows-local
```

共享基础能力先放在：

```bash
git switch future/windows-base
```

禁止在 `future/windows-local` 中实现课堂版专属内容，例如：

- 50 人局域网承载目标。
- 局域网访问地址面板。
- 课堂版视频分发优化。
- 课堂版学习进度写入节流策略。

如果实现过程中发现单机版和课堂版都需要的能力，应先回到 `future/windows-base` 实现，再合并到 `future/windows-local`。

## 3. 当前基础层状态

`future/windows-base` 已完成的公共能力：

- 新增 `APP_EDITION` / `app_edition` 运行形态。
- 支持 `development`、`windows_local`、`windows_classroom`、`server`。
- Windows 版本默认回落到本地 SQLite 文件库。
- Windows 版本默认缓存后端解析为 `diskcache`。
- 开发环境默认使用内存缓存。
- 服务器版默认缓存后端解析为 Redis。
- 启动时自动创建运行目录。
- SQLite 文件库启用 `busy_timeout`。
- 课堂版基础层预留 WAL 初始化。
- 新增运行配置与缓存抽象测试。

单机版后续只需要在此基础上补“安装、启动、初始化、用户体验”相关能力。

## 4. 运行配置契约

单机版必须使用：

```env
APP_EDITION=windows_local
```

推荐默认配置：

```env
APP_EDITION=windows_local
HOST=127.0.0.1
PORT=8000
CACHE_BACKEND=auto
```

数据库默认不要求用户配置：

```text
未设置 DATABASE_URL -> 自动使用本地 SQLite 文件
```

默认本地数据目录：

```text
project_code/backend/data/
```

后续打包时可以调整为 Windows 用户数据目录，例如：

```text
%APPDATA%/LearningPlatform/data/
```

但无论目录如何变化，都必须由程序自动创建，不能要求用户手动新建。

## 5. 数据库实施细则

### 5.1 数据库选择

单机版使用 SQLite 文件数据库，不内置 MySQL。

原因：

- 降低安装复杂度。
- 避免用户接触数据库服务。
- 更适合单机、离线、小规模使用。
- 数据文件容易备份和迁移。

### 5.2 初始化要求

首次启动必须自动完成：

1. 创建本地数据目录。
2. 创建 SQLite 数据库文件。
3. 创建所有表结构。
4. 执行历史 schema 兼容检查。
5. 导入必要种子数据。
6. 创建上传目录、日志目录、缓存目录。

重复启动必须幂等：

- 不能重复插入管理员账号。
- 不能重复插入分类、标签、课程种子。
- 不能覆盖用户已有上传文件。
- 不能删除用户已有学习记录。

### 5.3 用户不可见原则

单机版不应暴露：

- 数据库命令行。
- MySQL 安装步骤。
- Redis 安装步骤。
- 手动执行 `init_db.py`。
- 手动执行 `seed_data.py`。

如果初始化失败，应展示用户能理解的错误提示，并把详细原因写入日志。

## 6. 缓存实施细则

单机版默认使用：

```text
diskcache
```

适合缓存：

- 首页课程列表。
- 课程详情基础信息。
- 分类列表。
- 标签列表。
- 公告列表。
- 权限码/角色权限等读多写少数据。

禁止放入 `diskcache`：

- 视频文件本体。
- 大图片原文件。
- 大课件原文件。
- 上传文件原始内容。
- 视频分片流。

这些资源应由静态文件服务和浏览器缓存处理，不应进入业务缓存层。

## 7. 静态资源与前端打包

单机版最终交付应包含：

- 前端 `npm run build` 后的静态产物。
- 后端 Python 运行环境或打包后的可执行后端。
- 启动器或脚本。
- 默认配置文件。
- 本地数据目录初始化逻辑。

前端生产构建要求：

- JS/CSS 文件名带 hash。
- 浏览器可长期缓存带 hash 资源。
- API 仍保持 `/api/v1` 口径。
- 上传文件仍通过 `/uploads` 或后续静态服务路径访问。

## 8. 启动器实施细则

第一阶段可以先做 Windows 启动脚本，不必立刻做完整安装器。

启动器职责：

1. 设置 `APP_EDITION=windows_local`。
2. 确认本地运行目录存在。
3. 启动后端服务。
4. 启动或提供前端静态文件服务。
5. 等待健康检查通过。
6. 自动打开浏览器。
7. 后端异常时保留窗口并显示日志位置。

### 8.1 启动验证契约

启动器只有在以下条件都满足时，才能提示“启动成功”并打开浏览器：

1. 默认配置文件存在并已加载。
2. Python 运行环境或后端可执行文件存在。
3. 目标端口未被其他进程占用。
4. 前端生产包存在；如果不存在，自动构建成功。
5. 后端进程已启动，且健康检查在超时时间内返回 2xx～4xx 响应。
6. 日志目录可写，启动日志和错误日志路径已明确输出。

失败时必须保留窗口，并至少展示：失败原因、建议处理方式、启动日志路径、错误日志路径。失败不应静默吞掉，也不应让用户只能看到窗口闪退。

### 8.2 打包与安装边界

当前阶段允许的交付形态是：

```text
zip/解压目录 + 默认配置 + 前端 dist + 后端运行环境 + start-windows-local.cmd
```

完整安装器放到后续阶段，不阻塞当前单机版可用性验证。安装器阶段再考虑：

- 创建桌面快捷方式。
- 写入默认配置。
- 支持卸载程序。
- 卸载时默认不删除用户数据，除非用户明确选择。
- 后续从解压版迁移到安装版时的数据迁移说明。

### 8.3 数据保留契约

无论使用解压包还是安装器，默认都不能删除用户数据：

- SQLite 数据库文件默认保留。
- `uploads` 中的上传文件默认保留。
- `logs` 可按日志轮转策略清理旧日志，但不应在升级时直接清空。
- `data/cache` 可重建，允许在明确说明后清理。
- 程序更新不能覆盖用户已有数据库和上传目录。

## 9. 安全边界

单机版仍需要保留：

- Bearer Token 登录态。
- 角色权限判断。
- 后台管理权限。
- 上传文件类型和大小校验。

单机版不需要实现：

- 公网暴露。
- 多机数据库访问。
- Redis 会话共享。
- 集群能力。

默认监听应优先使用本机地址：

```env
HOST=127.0.0.1
```

如果未来允许局域网访问，应转入课堂版分支实现。

## 10. 实施阶段

### Phase 1：基础配置接入

状态：已在 `future/windows-base` 完成。

内容：

- `APP_EDITION=windows_local`。
- SQLite 文件数据库默认值。
- diskcache 默认值。
- 运行目录自动创建。
- 启动时 schema 兼容检查。

### Phase 2：自动初始化补齐

目标：首次启动自动完成建表和种子数据导入。

重点文件：

- `project_code/backend/app/main.py`
- `project_code/backend/app/core/db_schema.py`
- `project_code/backend/scripts/init_db.py`
- `project_code/backend/scripts/seed_data.py`

验收：

- 删除本地 SQLite 文件后首次启动可自动恢复可用状态。
- 重复启动不会重复插入数据。

### Phase 3：单机启动脚本

目标：用户双击即可启动。

可能新增：

- `start-windows-local.cmd`
- `config/windows-local.env`

验收：

- 不需要打开命令行手动输入数据库命令。
- 启动后自动打开浏览器。
- 失败时提示日志位置。

### Phase 4：前端静态产物集成

目标：前端生产包随单机版一起分发。

验收：

- 不依赖 Vite dev server。
- 页面可访问后端 `/api/v1`。
- 上传资源可正常加载。

### Phase 5：安装器

目标：形成可交付安装软件。

可选路线：

- 先压缩包 + 启动脚本。
- 再 NSIS/Inno Setup 安装器。
- 后续再考虑更完整的桌面外壳。

## 11. 验证清单

后端验证：

```bash
project_code/.venv/bin/python -m pytest project_code/backend/tests/test_runtime_config.py -q
```

单机版专项验证：

- 设置 `APP_EDITION=windows_local` 后启动后端。
- 确认 SQLite 文件自动创建。
- 确认 `data/cache` 自动创建。
- 确认无 Redis 服务时仍可启动。
- 确认 `/docs` 和 `/api/v1/...` 可访问。
- 确认上传目录可自动创建并挂载。

前端验证：

```bash
cd UI
npm run build
```

联调验证：

- 使用种子账号登录。
- 打开首页、课程详情、学习页。
- 上传课程资源或封面。
- 重启程序后确认数据仍存在。

## 12. 验收标准

Windows 单机版达到可用状态时，应满足：

- 普通用户不需要安装 MySQL。
- 普通用户不需要安装 Redis。
- 普通用户不需要执行数据库初始化命令。
- 首次启动自动建库、建表、初始化必要数据。
- 重复启动不破坏已有数据。
- 页面可正常访问。
- 登录、课程浏览、学习、上传等核心流程可用。

## 13. 明确不做

单机版第一阶段不承诺：

- 50 人同时访问。
- 公网部署。
- 集群扩容。
- 多 Windows 主机共享同一数据库。
- 把视频文件放进 `diskcache`。

这些内容属于课堂版或 Linux 服务器版范围。
